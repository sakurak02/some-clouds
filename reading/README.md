# Readingの管理

## 本の追加

1. `templates/reading.md`をコピーし、`reading/books/r0001.md`のような名前で保存します。
2. 次の本は`r0002.md`、`r0003.md`と登録順に番号を増やします。4桁以上の連番を使い、一度使った番号は他の本に使い回さないでください。
3. 書誌情報とメモを記入します。ObsidianのプロパティとMarkdownのまま管理できます。
4. `npm run build`で本棚と個別ページ、サイトマップに反映します。既存の公開ワークフローもこのコマンドを実行します。

本棚は登録番号の降順です。読書開始日や更新日時で順番が変わることはありません。通し番号はファイル名から表示されるため、本文に書く必要はありません。

```markdown
---
title: 本のタイトル
author: 著者名
pages: 200
start: 2026-10-18
end:
status: 読書中
---

## p. 12

- 1つめのメモ。
- 同じページの別のメモ。

## p. 24

- 次のページのメモ。

## p. 12

- あとから書いた追記。
```

- `title`、`author`、`pages`、`start`、`status`は必須です。`pages`は正の整数、日付は`YYYY-MM-DD`です。
- `status`は`読書中`または`読了`を使います。読み終えたら`end`に終了日を入れ、`status: 読了`に変更します。
- 読書中の`end`は空欄にできます。個々のメモに日付は付けません。
- `## p. 12`の下に箇条書きで記録します。ページ番号は1〜総ページ数の範囲です。
- ページの見出しはどこに追記しても構いません。ビルド時に同じページをまとめ、ページ番号の昇順に表示します。同じページ内のメモは書いた順を維持します。
- 太字、斜体、通常のMarkdownリンクなどはDevelopmentと同じ表示処理を使います。インデントした続きの行も同じメモとして扱います。
- HTMLの個別ページは`reading/notes/r0001.html`に自動生成します。生成ファイルは直接編集せず、Markdownを編集してください。

## 確認用の架空本

`scripts/fixtures/reading/r0001.md`は、架空の本・架空のメモだけを使ったテスト専用データです。通常のビルドでは読み込まれず、本番の本棚には表示されません。

手元で本棚に表示する場合だけ、`reading/books/r0001.md`へコピーしてください（同名ファイルがある場合は別の未使用番号にします）。確認後にコピー先のMarkdownを削除して`npm run build`を実行すると、個別HTMLと本棚・サイトマップのリンクも除去されます。`scripts/fixtures/`内の元データはテスト用として残せます。

`npm test`で読み込み・並び順・追記・入力チェック・削除後の生成ページの整理を確認します。`npm run build:reading`はReadingだけの表示確認用です。公開前にはサイトマップも更新する`npm run build`を実行してください。
